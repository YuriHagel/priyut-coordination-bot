

# Пользовательские истории системы координации автоволонтеров «Приют»

**Проект:** `priyut-coordination-bot`  
**Версия документа:** 1.0  
**Дата:** 17.10.2026

Документ содержит пользовательские истории, критерии приемки и трассировку к требованиям ТЗ.

---

## 1. Роли

| Роль | Описание |
|---|---|
| Пользователь | Человек, который впервые открыл бота и еще не зарегистрирован |
| Волонтёр | Зарегистрированный и одобренный автоволонтёр |
| Администратор | Пользователь из белого списка Telegram ID |
| Система | Автоматические сценарии: напоминания, удаление, архивация |
| Оператор / разработчик | Техническая роль для развертывания и передачи Фонда |

---

## 2. Приоритеты

| Приоритет | Значение |
|---|---|
| Высокий | Обязательно для MVP |
| Средний | Желательно для MVP, если не ломает срок |
| Низкий | Можно перенести на следующую итерацию |

# Эпик 1. Регистрация и согласие на обработку ПДн

## US-REG-01. Первый запуск бота

**Как** пользователь  
**я хочу** отправить `/start` и увидеть информацию о боте  
**чтобы** понять, что это за сервис и как зарегистрироваться

### Критерии приемки

- Бот приветствует пользователя.
- Бот отправляет файл `Politika_PDN_Priyut.pdf`.
- Бот показывает текст согласия с версией документа.
- Показываются кнопки:
  - `Зарегистрироваться`;
  - `Как это работает` — опционально.
- До нажатия кнопки «Зарегистрироваться» согласие не фиксируется.

### Требования

- 4.1, шаг 1–4
- N1, N6

### Приоритет

Высокий

**чтобы** явно дать согласие на обработку персональных данных

## US-REG-03. Пошаговое заполнение анкеты

**Как** пользователь  
**я хочу** последовательно ввести имя, телефон, район, автомобиль и доступность  
**чтобы** стать кандидатом в автоволонтёры

### Критерии приемки

- Бот запрашивает:
  - имя;
  - телефон;
  - район;
  - автомобиль;
  - дни доступности;
  - время доступности.
- Телефон валидируется, ожидается формат `+7...`.
- Район можно выбрать кнопками или ввести вручную.
- Дни недели выбираются чекбоксами: Пн, Вт, Ср, Чт, Пт, Сб, Вс.
- Время доступности выбирается или вводится текстом.
- В конце показывается сводка анкеты.
- Анкета сохраняется со статусом «На модерации».

### Требования

- 4.1, шаг 5–6
- F1, F11

### Приоритет

Высокий

## US-REG-04. Уведомление администратора о новой анкете

**Как** администратор  
**я хочу** получать уведомление о новой анкете  
**чтобы** проверить волонтера и одобрить или отклонить его

### Критерии приемки

- После сохранения анкеты администратор получает сообщение.
- В сообщении указаны:
  - имя;
  - телефон;
  - район;
  - автомобиль;
  - доступность.
- Администратор может подтвердить или отклонить анкету.
- При подтверждении статус волонтёра становится `ACTIVE`.
- При отклонении статус становится `REJECTED`, волонтёр получает уведомление.

### Требования

- 4.1, шаг 7
- F2, F3

### Приоритет

Высокий

**чтобы** закрепить поездку за ним

  - имя;
  - телефон;

# 3. Сквозные критерии качества

Каждая пользовательская история должна удовлетворять следующим критериям:

- Доступ к админ-функциям только из белого списка.
- Персональные данные не попадают в логи.
- Все изменения статусов поездок пишутся в историю.
- Все действия с согласием ПДн пишутся в журнал.
- Ошибки показываются пользователю дружелюбно и без технических деталей.
- Критичные сценарии покрыты тестами.
- Миграции БД версионируются через Flyway.

# 5. Definition of Done

История считается завершенной, если:

- реализован сценарий;
- обновлены миграции БД при необходимости;
- написаны юнит-тесты;
- написаны интеграционные тесты для критичных сценариев;
- проверены права доступа;
- проверены уведомления;
- обновлена история событий;
- нет секретов в коде;
- нет персональных данных в логах;
- код собран через `./gradlew build`;
- сценарий проверен вручную на тестовом боте.
